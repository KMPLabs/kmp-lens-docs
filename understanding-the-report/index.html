Report guide

Understanding the report

The report answers practical developer questions: which Apple framework was observed, which module produced it, what the run established, which dependencies participate, what each Apple symbol represents, where it comes from, how it reaches the producer, and where KMP Lens’s knowledge stops.

Report sections

Overview

Identifies the observed framework, producer and target. When KMP Lens is applied outside the producer module, the overview distinguishes the plugin’s observation point from the module that actually produced the framework.

It also records the KMP Lens version and revision, report timestamp, source mode, scoped compatibility and KMP Lens’s own duration for this run.

Compatibility is classified by knowledge family. One unverified family does not invalidate independently qualified Kotlin/Native, Gradle, source or integration knowledge.

Run Summary

Summarizes the Apple-symbol and Origin populations established by the run, plus the observed architecture outcome and any qualified plugin contribution. Run identity remains in Overview instead of being duplicated here. KMP Lens does not label a build cold or warm without a dedicated performance authority.

Dependencies

Shows the local and Maven dependencies directly observed from the analyzed producer. A dependency path is an observed route through the graph; it is not a claim that every edge was declared with a particular Gradle DSL expression.

The dependency graph does not reconstruct Gradle source files. A component can be resolved without KMP Lens claiming which build-script line declared it.

Investigate

Start with one of four counted populations:

Population What it means
Exact origin The owner of this exact declaration is established.
Generated support The exact form is identified as generated by Kotlin/Native or SKIE; this is not an application Origin.
Context only Useful surrounding information is established, but not an exact owner or generated-form answer for this symbol.
Not established The run has not established one of those answers for this exact symbol.

These populations do not overlap. Summary and navigation count the same Apple symbols. A type and each of its members are separate symbols even when shown inside a single result card. Generated-support counts combine the Kotlin/Native and SKIE counts in the automation summary.

Choose a population, then an exact owner, generator or observed context group, then a symbol card. Large APIs do not require paging through a flat list to find a starting point. Flat browsing remains available explicitly. Context groups describe surrounding information, not ownership of every symbol inside.

Search and filters

Search is global to the framework, even when Browse filters are retained. Its scope is shown next to the search field. Use it directly when you know an Apple symbol; an exact match takes priority over partial matches.

Browse can combine population and direct-dependency filters. Active constraints stay visible and can be removed independently. An empty intersection stays empty—it does not silently show another population. Filters change the view, not the facts known about a symbol.

Results use pages of 10 cards. Opening a detail and returning preserves the population, group, filters, search, page and position. Every detail retains its own declaration Origin, provider, Why you see it, source, generator, relationships, context and paths where available.

Reading a declaration

Each result describes one exact Apple symbol. Members may be grouped below a type to make browsing easier, but every member keeps its own answer.

Why you see it

Explains why this exact symbol is visible in the observed Apple API when the run can establish a useful reason. It can describe Kotlin visibility, observed framework participation, dependency reachability, or a qualified generated form. A dependency route alone is not presented as proof that a symbol was explicitly exported.

Origin

Names the established owner of the exact declaration, such as a local Gradle module, a Maven component, or the Kotlin standard library. Origin is not copied from a parent type to a member, or from a member to its parent.

Provided by

Names the component that supplies the observed declaring artifact when that role is independently established. Provider and declaration Origin can have the same displayed component, but KMP Lens does not treat the two roles as synonyms.

Relationships

Explains why a member belongs on its exact container when the final header and complete member identity establish a protocol requirement, inherited declaration, extension, category or generated-support relation. Several compatible protocol requirements remain several valid relationships; they are not collapsed into an arbitrary first match. A relationship never establishes the owner of the concrete implementation by itself.

Generated by

Identifies a qualified tool that generated the exact Apple form, currently Kotlin/Native or SKIE in their verified configurations. A generated form does not automatically have a separate application Origin.

Context

Shows exact surrounding information that is useful but does not belong to the symbol itself—for example, its exact container or what the observed members of a container have in common. Context does not become Origin or a dependency path.

Kotlin Source

Shows an authorized local source correspondence when SOURCE ON is enabled and the run can establish one. A single compatible candidate and multiple possible candidates remain visibly different from an exact source attachment. SOURCE OFF omits this section without removing independently established knowledge.

Gradle Source

Shows the exact build declaration responsible for one dependency edge when the run observes the declaration, its model effect and the resolved edge as one chain. It is distinct from Kotlin Source: Gradle Source explains a build decision, not declaration ownership. A convention-plugin dependency points to the responsible plugin source rather than the consumer script.

Potentially sensitive declarations are hidden completely. KMP Lens shows only a project-relative path, line and minimal safe snippet; it never exposes an absolute machine path. When a plugin or build tool adds an edge without an exact repository source, the report explains that limit and shows no snippet. For Maven-to-Maven transitive edges, the report says published dependency metadata unless the responsible metadata format is itself established; it does not invent a local Gradle declaration.

Dependency paths

Shows observed routes through the resolved Gradle graph from the producer to an established Origin. The card starts with a representative route and keeps all observed routes accessible. These paths explain reachability; they do not reconstruct the Gradle build script.

Evidence used, real limitations and advanced evidence

Evidence used identifies the authority path that established the result. Real limitations contains only facts that limit that conclusion. An unavailable alternative path for an independently established result appears under Advanced evidence, not as uncertainty about the result.

Compatibility

Compatibility is reported by knowledge family with two separate questions. Observed / Not observed says whether KMP Lens acquired that family’s input in this run. Qualified / Unverified says whether the minimum authority needed for that family matches an exercised scope. Unverified / best effort still continues without a compatibility promise. Not active means an optional integration was not present, and out of scope means that family does not apply. One unverified family does not erase independently qualified answers.

What “stops here” means

The report shows the strongest available answer for each relevant dimension. “Not determined” means that the dimension could apply but the current run did not establish it sufficiently. Dimensions that do not apply are omitted rather than displayed as unknown.

For release qualification, every applicable symbol dimension must have either an established result or one explicit terminal boundary: legitimately not established, information unavailable, ambiguous, adapter missing, or not applicable. Population parity alone does not prove this completeness.

One symbol, one answer

Search and browsing show the same established knowledge for the same Apple symbol. Grouping a type with its members is a browsing convenience only: a member does not automatically inherit its parent’s Origin, source, explanation or dependency paths, and a parent does not inherit answers from its members.

Automation

Do not parse the HTML DOM for automation. The small, privacy-minimized automation contract is documented on the Continuous integration page.
